# 接口与数据结构说明

## 一、命令行入口（`schem_gen.py`）

所有命令默认纯本地离线执行，无网络访问、无 SSH 连接、无电路仿真调用；输出目录自动创建。

| 子命令 | 用途 | 核心输入 | 核心输出 |
| :--- | :--- | :--- | :--- |
| `analyze` | 解析网表、执行通用竖向支路折叠 + 偏置树剥离 + Pass 0–3 语义分析，生成草案与 LLM 双视角简报 | `.spice` / `.cdl` / `.scs` 网表 | `analysis.json`, `intent.draft.json`, `module_plan.draft.json`, `semantic_digest.md` |
| `inspect` | 只读局部信号邻域追踪（`--around`，自动隐藏全局偏置轨）与 Stage-2 模块局部聚焦视窗（`--module`） | 网表 + 支路/器件/网络目标 | 终端 Markdown / JSON（或 `--out` 文件） |
| `validate-modules` | 布局前置语义审计（校验 100% 器件覆盖、HARD 原子段不撕裂（`TORN_ATOMIC_BRANCH`=ERROR，仅软连接点分属记 `SPLIT_AT_SOFT_JOINT`=WARNING）、模块内聚、跨模块割边与镜像骨架兼容性） | 网表 + `module_plan.json` 或 `intent.json` | `module_audit.json`, `module_audit.md` |
| `plan-to-intent` | 将通过语义校验的粗到细 `module_plan.v1` 确定性展开为完整 `intent.json`（自动推导朝向、纵层与列序） | 网表 + `module_plan.json` | 完整 `intent.json` |
| `compile` | 按确认后的 `--intent` 或 `--module-plan` 执行约束布局、正交分轨布线、SVG 渲染与双重签核 | 网表 + (`--intent` 或 `--module-plan`) + `process-map` | `manifest.json`, `canvas_ir.json`, `preview.svg`, `audit.json`, `audit.md`（使用 `--module-plan` 时附带 `module_audit.md`, `intent.expanded.json`；含黑盒 `.subckt` 块时自动注册框符号并附带 `augmented_process_map.json`） |
| `auto` | 零样本全自动模式（直接采用 `analyze` 生成的草案 `Intent` 编译） | 网表 | 同 `compile` + `analysis.json`, `semantic_digest.md` |
| `partition` | 对大规模扁平网表提出原子簇保护的多页切分草案 | 大规模网表 | `hierarchy_intent.draft.json` |
| `hierarchy` | 多页层次化编译、展平还原 LVS 校验与交互式 HTML 原理图册生成 | 网表 [+ `hierarchy_intent.json`] | `index.html`, `combined_manifest.json`, `hierarchy_summary.json`, `sheets/*` |
| `extract-pdk` | 从 Xschem `.sym` 目录或已授权实机 Virtuoso 只读提取 `process-map` | `--from-xschem` 或 `--from-virtuoso --live` | `<pdk>_process_map.json` |
| `export-editor` | 导出零依赖单文件浏览器拖拽/翻转微调画布 | 网表 [+ `intent.json`] | `editor.html` |
| `refine` | 保结构整理既有草图（保留原图行列顺序与朝向，撑开过挤区、收紧过大空白并重布线） | 既有 `manifest.json` | 整理后 `manifest.json`, `preview.svg`, `refine_comparison.json` |
| `audit` | 独立对任意 `virtuoso-bridge-exact-schematic-v1` 清单做 LVS + 可读性 DRC | `manifest.json` [+ 基准网表] | `audit.json`, `audit.md` |
| `probe-pdk` | 校验已授权 Virtuoso 会话中的真实符号引脚偏移（未加 `--live` 时仅打印离线说明） | `--pdk-map` [--live] | 终端核对结果 / JSON |
| `demo` | 一键运行内置 4 组 SKY130 代表性基准案例 | `--out <dir>` | 4 组完整产物 + `demo_summary.json` |

### `analyze` 语义分析产物（v0.3.1 Coarse-to-Fine 升级）

- **`semantic_digest.md` / `semantic_digest_full.md`（分级简报）**：默认摘要版控制篇幅——支路数超过 `digestFullTableMaxBranches`（默认 30）时只列核心锚点涉及的支路，其余按类型列编号；支路纯信号边仅在支路数不超过 `digestSignalEdgesMaxBranches`（默认 20）时内联，否则提示用 `inspect` 追线；各类长列表截断。完整版输出全部内容。简报第 5 节固定声明“器件编号/网络名只作平局裁决”，并列出左右由编号决定的差分对。
- **`semantic_digest.md`（面向 LLM 的双视角粗到细简报）**：在保留 Pass 0–3 信号流主干与瓶颈割的基础上，新增：
  - **竖向支路折叠地图（`BR01..BRk`）**：把 MOS/BJT/无源串联链按 `VDD→VSS` 无损折成竖向支路并隐藏纯串联内部节点；
  - **偏置分配树 vs 纯信号耦合**：自动分离高扇出二极管/端口偏置轨（`scope=global`），剥离偏置噪声后显式列出**闭环反馈回路（`LOOP*`）**、**跨器件类型准对称候选（`QSYM_*` / `QSYM_COUPLED_*`）**、**规整列阵列（`ARR_*`）**及排序后的**核心电路锚点候选（`Core Anchors`）**。
- **`module_plan.draft.json`（`schem_gen.module_plan.v1` 草案）**：面向复杂电路的轻量级从粗到细契约，大模型只需填写模块归属（引用 `BRxx` 支路号，草案在软连接点拆分处用 `instances` 补齐）、`isCore` 核心标记、`evidence` 拓扑依据及可选模块骨架 `skeleton`（`mirror_pair` / `bias_bank` / `parallel_array` / `horizontal_bridge`），**无需手写几十个单器件朝向与纵层**。未改动的草案与 `intent.draft.json` 器件归属完全一致、编译结果相同；算法检出的未覆盖准对称对以 `suggestedSkeleton` 给出，改名为 `skeleton` 后才生效。展开时未声明骨架的部分继承分析器的列序、基元、朝向、纵层与网络策略。
- **支路 `hardSegments` / `jointKinds`**：每条折叠支路的相邻连接点标为 `hard`（纯串联私有节点或同一 Super-MOS 叠管）或 `soft`（多器件抽头节点）。HARD 段是全工具唯一的不可拆单元定义，`analyze` 草案、`partition`/`hierarchy` 分页与 `validate-modules` 共用。
- **`analysis.json` 字段**：
  - `branchAbstraction`：通用支路折叠、偏置树、纯信号边、共享信号母线、反馈环、准对称对、规整阵列与核心锚点结构化 JSON；
  - `deviceRoles`：逐器件功能角色字典（含 MOS 与 `bjt_diode` / `bjt_follower`，纯端口拓扑驱动）；
  - `signalBackbone`：块级有向信号流 DAG（`blocks`, `edges`, `cutNets`, `selectedCutNets`, `macroStages`, `boundaryAmbiguousBlocks`, `crossStageNets`）。

## 二、`SchematicIntent`（`schem_gen.intent.v1`）字段契约

`intent.json` 是大模型与底层几何求解器之间的唯一控制面，**不含任何像素或浮点坐标**：

  "groups": [
    {
      "id": "input_diff",
      "label": "第一级差分输入",
      "role": "input_diff",
      "stage_order": 10,

### 枚举值说明

1. **`orientations`（器件语义朝向）**
   - `gate_left`（对应 Virtuoso `R0`）：MOS 栅极朝左，沟道在右（PMOS 源在上漏在下，NMOS 漏在上源在下）。
   - `gate_right`（对应 Virtuoso `MY`）：MOS 水平镜像，栅极朝右，沟道在左，上下源漏方向保持不变。
   - `horizontal_gate_down` / `horizontal_gate_down_flipped`（对应 Virtuoso `R90` / `MXR90`）：MOS 水平旋转，沟道左右走向、栅极朝下、体端短桩自动垂直朝上（适用于 Miller 调零有源 MOS 电阻、传输门与水平桥接管）。
   - `horizontal_gate_up` / `horizontal_gate_up_flipped`（对应 Virtuoso `R270` / `MYR90`）：MOS 水平旋转，沟道左右走向、栅极朝上、体端短桩自动垂直朝下。
   - `vertical` / `vertical_flipped`（`R0` / `MX`）：二/三端无源器件或独立源垂直摆放（`P` 在上 `M` 在下，或翻转）。
   - `horizontal_l2r` / `horizontal_r2l`（`R90` / `R270`）：无源器件水平摆放（`P` 在左 `M` 在右，常用于级间米勒补偿电容/调零电阻）。
2. **`tierOverrides`（纵向电位层 `1..5`）**
   - `1`：顶层 PMOS（源接 `VDD`）或高端电流源；
   - `2`：PMOS 共源共栅叠管（Cascode）；
   - `3`：中间信号带（水平跨接 RC 补偿、耦合电容等）；
   - `4`：NMOS 差分对或 NMOS 共源共栅叠管；
   - `5`：底层尾流管、NMOS 电流镜负载或接地负载电容（源/负端接 `VSS`）。
3. **`netPolicies`（网络走线策略）**
   - `supply_local`：电源/地（或指定重复顶层端口）就近生成局部垂直/水平短桩抽头，不拉全局横跨线；
   - `bulk_local`：MOS 体端与源同网时生成就地短环（`localBulkShorts`），接顶层电源/偏置端口时生成短桩标签（`localBulkLabels`）；
   - `full_wire`：通过正交 Steiner 树就近连通全部端子；
   - `perimeter_bus`：保持物理单连通正交实线（满足 Virtuoso `schCheck` 内部网不断网要求），但引导水平主干沿底部外围母线走廊布设，避开核心信号区。
4. **`portSides`（顶层端口摆放方式）**
   - `near_pin`：紧贴目标器件栅极/引脚外侧生成水平端口旗标（最适合差分输入对 `VINP`/`VINN`）；
   - `left` / `right` / `top` / `bottom`：置于原理图外框对应侧；
   - `local_repeat`：对电源/地或多支路共用的顶层偏置端口，在各受控支路旁生成同名重复端口（`virtuoso-bridge-lite` 原生支持同名 `inputOutput` 端口自动合并到同一电气网络）。

## 三、`AuditReport`（`schem_gen.audit.v1`）签核门禁定义

`overallPassed = true` 要求以下三项同时为 `true`：
1. **`bridgeManifestValid`**：通过 `virtuoso-bridge-lite` 的 `load_schematic_manifest`、`load_process_map` 与 `plan_manifest_circuit` 校验，且 `afterViolationCount == 0`；
2. **`electricalPassed`**：实例集合、全部参数（`w/l/nf/m` 等）、含体端 `B` 在内的有序端子网络划分与输入网表 100% 一致，且所有内部网络在物理导线上构成单一连通分量（无 `SPLIT_INTERNAL_NET`）；
3. **`readabilityPassed`**：以下 6 项硬性几何违例全部为 `0`：
   - `symbolOverlapCount == 0`（器件本体无重叠）
   - `labelOverlapCount == 0`（参数文字与相邻符号、相邻文字及任何导线无重叠）
   - `wireThroughBodyCount == 0`（无导线穿过无关或自身符号内部）
   - `wireOverForeignPinCount == 0`（无导线擦过异网引脚）
   - `collinearForeignWireOverlapCount == 0`（无异网平行线段共线重叠）
   - `ambiguousCrossingCount == 0`（无拐角或 T 型接点落在异网导线上）

## 四、模块分层与集中规则（v0.3.3）

| 层 | 模块 | 允许依赖 |
| :--- | :--- | :--- |
| 核心契约 | `models.py`、`topology_core.py`（端口角色原语、默认纵层、Super-MOS 叠管、器件族、阈值、走线策略优先级） | 仅 `models` |
| 解析与工艺 | `parser.py`、`pdk.py`、`pdk_extractor.py` | 核心契约 |
| 前端语义 | `topology_semantics.py`、`branch_abstraction.py`、`analyzer.py`、`semantic_digest.py`、`semantic_validator.py` | 核心契约、解析；语义层之间只用公开名（如 `analyzer.order_columns_and_orient_gates`） |
| 布局布线 | `placer.py`、`router.py`、`optimizer.py` | 核心契约、工艺；**不导入** `analyzer` / `auditor` / 语义层模块（由测试强制）；优化代价经 `cost_fn` 注入 |
| 编排 | `hierarchy.py`（分页、逐页编译、页审计）、`schem_gen.py`（CLI） | 以上全部 |
| 签核与输出 | `auditor.py`、`quality.py`、`hierarchy_lvs.py`、`hierarchy_book.py`、`svg_renderer.py`、`manifest_builder.py`、`interactive_editor.py`、`refiner.py` | 以上全部（不含编排层） |

### 走线策略来源与优先级（`intent.netPolicySources`）

`llm`（`module_plan.netPolicies` / `overrides.netPolicies`，或人工编辑的 intent）> `skeleton`（骨架展开补全的全局偏置母线）> `optimizer`（消交叉自动提升）> `analyzer`（草案默认值）。优化器只改动来源为 `analyzer` / `optimizer` 的网络。`label_stub` 在未开启 `--allow-wire-labels` 时按 `perimeter_bus` 实线处理，并在 `audit.json` 中报告 `LABEL_STUB_DEGRADED` 与 `metrics.degradedLabelStubNets`。
